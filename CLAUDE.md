# HousePlan — инструкции для агентов

Веб-приложение для планирования расстановки мебели в помещениях. Что это за
программа и зачем — в `README.md`. Исходная постановка от заказчика — в `task.txt`.

## Язык общения и документации

**Всё пишем по-русски** — ответы в чате, документация, комментарии в коде,
сообщения коммитов, названия и описания задач.

В команде есть участники без опыта программирования. Поэтому:

- Объясняем нормальным человеческим языком, а не набором терминов.
- Если технический термин действительно нужен (без него никак) — при первом
  упоминании поясняем в скобках, что он значит.
- Не пересказываем очевидное на жаргоне: «сохранили файл» лучше, чем
  «выполнили персистентность артефакта».
- Сначала суть и результат, потом — подробности реализации для тех, кому надо.

Исключения, где английский остаётся: сам код (имена переменных, функций,
классов), названия команд и библиотек, метки задач в GitHub.

## На какой стадии проект

**Проектирование. Кода нет.** Сейчас мы отвечаем на вопросы о том, как программа
должна себя вести, и складываем ответы в техническое задание. Писать код рано —
половина решений ещё не принята.

Ход работы ведётся картой пути на GitHub:
[Карта: техническое задание на планировщик мебели](https://github.com/UncleHobbot/HousePlan/issues/1).
Карта — это задача с меткой `wayfinder:map`, к ней прицеплены дочерние задачи, у
каждой свой вопрос. Как с ней работать — `docs/agents/issue-tracker.md`, раздел
«Работа с картой пути».

**Начиная сессию по проектированию — сначала прочитай карту.** В ней записан пункт
назначения, принятые решения и то, что вынесено за границу работы.

## Что уже решено

Эти решения приняты вместе с заказчиком и не пересматриваются без разговора.

| | |
|---|---|
| Пользователи | Один. Профилей, регистрации и входа по паролю нет |
| Где работает | Synology DS923+ в контейнере Docker, только домашняя сеть |
| Чем пользуются | Компьютер с мышью. Планшет и телефон не поддерживаем |
| Объёмы | Единицы домов, единицы помещений, десятки объектов |
| База данных | Отдельной нет и не планируется — объёмы крошечные |
| Размеры | Сантиметры, целые числа |
| Черчение | Рисуем на глаз, отдельные участки «прибиваются» точным размером |
| Резервные копии | Отдельного механизма нет, файл копируется вручную |

**За границей работы:** искусственный интеллект для расстановки и поиска картинок,
3D-визуализация, обмен объектами между проектами. Эти вещи есть в исходной
постановке, но мы сознательно вынесли их за пределы первой версии. Не предлагай их
и не закладывайся на них.

## Как мы работаем

- **Доводи до конца.** Сделал файлы — сделай коммит и отправь на GitHub. Не надо
  оставлять человеку команду, чтобы он выполнил её сам.
- **Останавливайся перед необратимым.** Публичные репозитории, принудительная
  отправка с перезаписью, переписывание истории — только с разрешения.
- **Не выдумывай фактов.** Если чего-то не знаешь про сервер, библиотеку или
  намерения заказчика — спроси. Догадка, выданная за факт, дороже вопроса.
- **Одна задача карты за сессию.** Исключение — исследования, они идут параллельно.

## Настройки для агентов

### Где живут задачи

Задачи ведём в GitHub Issues этого репозитория, через утилиту `gh`. Внешние
pull request'ы в разбор задач **не** попадают. Подробности —
`docs/agents/issue-tracker.md`.

### Метки

Для разбора задач: `needs-triage`, `needs-info`, `ready-for-agent`,
`ready-for-human`, `wontfix` — подробности в `docs/agents/triage-labels.md`.

Для карты пути: `wayfinder:map` — сама карта, а тип задачи обозначается меткой
`wayfinder:grilling` (решается разговором), `wayfinder:research` (агент разбирается
сам), `wayfinder:prototype` (нужен черновик, который трогают руками) или
`wayfinder:task` (ручная работа, без которой не принять решение).

### Документация по предметной области

Одна общая область: `CONTEXT.md` и папка `docs/adr/` в корне репозитория.
Подробности — `docs/agents/domain.md`. Обоих файлов пока нет — они появятся, когда
в разговоре всплывут термины и решения, которые стоит записать.
