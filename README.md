# HousePlan

Программа для планирования расстановки мебели в доме. Рисуете помещение с
размерами, расставляете мебель перетаскиванием, сохраняете варианты расстановки и
сравниваете их между собой.

> **Проект на стадии начала разработки.** Проектирование закончено: техническое
> задание собрано в `docs/` из трёх частей (поведение, модель данных,
> технологии). Каркас кода есть; редактор планов в работе. Ниже — что задумано и
> как идёт работа.

## Зачем это

Когда переезжаешь в новый дом или задумываешь перестановку, хочется заранее понять,
влезет ли диван и останется ли место, чтобы пройти. Рулетка и лист бумаги работают,
но переделывать план на бумаге утомительно, а через месяц уже не вспомнить, почему
решили именно так.

Существующие программы либо слишком тяжёлые (полноценные системы проектирования),
либо не дают задать точные размеры, либо требуют регистрации и хранят ваш дом на
чужом сервере. Эта — простая, работает дома и никуда ничего не отправляет.

## Что программа умеет (задумано)

**Проекты.** Верхний уровень — дом: «Мой новый дом», «Дом детей». Внутри проекта
этажи, в этажах помещения.

**Черчение помещений.** Помещение рисуется на глаз, а затем отдельным участкам
задаются точные размеры — «от этого угла до того 250 см», — и остальной контур
подстраивается. Так удобно: сначала набросали форму комнаты, потом обошли её с
рулеткой и уточнили. Точки на углах ставятся сами, но можно добавить и вручную.

**Служебные зоны.** Лестница в подвал, встроенный шкаф, камин, декоративная
стена — то, что занимает место, но мебелью не является.

**Окна и двери** отмечаются на стенах. Любой зоне можно приписать описание и
свойства: цвет штор, насколько светло.

**Мебель.** У объекта есть размеры, цвет, передняя и задняя сторона, возможно
картинка. И допуски — свободное место вокруг, которое нельзя занимать: место для
ног под столом, проход перед шкафом.

Важная особенность: объект в проекте существует в одном экземпляре. Диван можно
перенести из гостиной в кабинет, но он не размножится — как в жизни.

**Варианты расстановки.** Можно сохранить несколько раскладок одного дома:
«Первоначальный вариант», «Фактически на октябрь 2026», «План на перестановку после
Нового Года» — и переключаться между ними.

## Чего программа делать не будет

Сознательно вынесено за пределы первой версии, чтобы не растянуть её на годы:

- Подбор расстановки искусственным интеллектом и поиск картинок мебели
- Трёхмерная визуализация
- Обмен объектами между разными проектами
- Несколько пользователей, регистрация, вход по паролю
- Работа с планшета и телефона

Часть этого есть в исходной постановке и, возможно, появится позже — но отдельной
работой, а не довеском к этой.

## Как идёт работа

Проектирование ведётся **картой пути** — задачей на GitHub, к которой прицеплены
вопросы, требующие решения:

**[Карта: техническое задание на планировщик мебели](https://github.com/UncleHobbot/HousePlan/issues/1)**

Каждый вопрос разбирается отдельно, ответ записывается, и карта показывает, что уже
решено, а что ещё нет. Задачи связаны между собой: часть нельзя брать, пока не
закрыты предыдущие. GitHub показывает это сам.

Работа считается законченной, когда не осталось решений, которые нужно принять до
начала написания кода.

## Что где лежит

| Путь | Что это |
|---|---|
| `task.txt` | Исходная постановка от заказчика, как она была написана |
| `README.md` | Этот файл — общее описание для человека |
| `CLAUDE.md` | Инструкции для агентов: правила, ограничения, состояние проекта |
| `docs/` | Техническое задание: поведение, модель данных, ADR — решения и почему так |
| `docs/agents/` | Настройки рабочих процессов: где задачи, какие метки, как ведём карту |
| `research/` | Находки исследований — что умеют существующие программы, какие есть библиотеки |
| `shared/` | Типы модели данных, общие для сервера и веб-части |
| `backend/` | Сервер: раздаёт приложение, читает и сохраняет файлы проектов |
| `frontend/` | Веб-часть: каталог проектов, план этажа; редактор — в работе |

## Разработка

Нужен Node.js 20+. Все команды — из корня репозитория:

```bash
npm install            # один раз
npm run build          # собрать всё: общие типы, сервер, веб-часть
npm run start          # запустить сервер: http://localhost:3000
```

Для правок веб-части удобнее режим разработки: в одном окне `npm run
dev:backend`, во втором `npm run dev:frontend` — и открывать адрес, который
покажет vite. Данные лежат в папке `data/` (в git не попадают): резервная
копия — скопировать папку.

## Где это будет работать

Домашний сервер Synology DS923+, контейнер Docker, доступ только из домашней сети.
Отдельная база данных не нужна: единицы домов и десятки объектов помещаются в файл.
