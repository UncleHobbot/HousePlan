# HousePlan

Программа для планирования расстановки мебели в доме. Рисуете помещение с
размерами, расставляете мебель перетаскиванием, сохраняете варианты расстановки и
сравниваете их между собой.

> **Первая версия собрана и работает.** Проектирование закончено, техническое
> задание лежит в `docs/`, и все его части реализованы: черчение помещений,
> служебные зоны, окна и двери, объекты со складом, расстановка перетаскиванием,
> варианты расстановки и приём карточек мебели снаружи. Ниже — что программа
> делает и как её запустить.

## Зачем это

Когда переезжаешь в новый дом или задумываешь перестановку, хочется заранее понять,
влезет ли диван и останется ли место, чтобы пройти. Рулетка и лист бумаги работают,
но переделывать план на бумаге утомительно, а через месяц уже не вспомнить, почему
решили именно так.

Существующие программы либо слишком тяжёлые (полноценные системы проектирования),
либо не дают задать точные размеры, либо требуют регистрации и хранят ваш дом на
чужом сервере. Эта — простая, работает дома и никуда ничего не отправляет.

## Что программа умеет

**Проекты.** Верхний уровень — дом: «Мой новый дом», «Дом детей». Внутри проекта
этажи, в этажах помещения.

**Черчение помещений.** Помещение рисуется на глаз, а затем отдельным участкам
задаются точные размеры — «от этого угла до того 250 см», — и остальной контур
подстраивается. Так удобно: сначала набросали форму комнаты, потом обошли её с
рулеткой и уточнили. Точки на углах ставятся сами, но можно добавить и вручную,
разрезав стену. Уже заданный размер «прибивается» замком: пока замок стоит, эта
часть контура не поедет.

**Служебные зоны.** Лестница в подвал, встроенный шкаф, камин, декоративная
стена, простенок — то, что занимает место, но мебелью не является. Лестница может
быть сквозной — проходить через несколько этажей.

**Окна и двери** отмечаются на стенах, с шириной, высотой и стороной открывания.

**Мебель.** У объекта есть размеры, цвет, передняя и задняя сторона, возможно
картинка. И допуски — свободное место вокруг, которое нельзя занимать: место для
ног под столом, проход перед шкафом. Программа подсказывает, когда объекты или их
допуски налезают друг на друга.

Важная особенность: объект в проекте существует в одном экземпляре. Диван можно
перенести из гостиной в кабинет, но он не размножится — как в жизни. Пока объект
никуда не поставлен, он лежит на складе.

**Варианты расстановки.** Можно сохранить несколько раскладок одного дома:
«Первоначальный вариант», «Фактически на октябрь 2026», «План на перестановку после
Нового Года» — и переключаться между ними. Сохранённый вариант можно сравнить с
текущим планом: программа покажет списком, что переехало, что добавилось и что
убрали, и подсветит переехавшее прямо на плане.

**Приём мебели снаружи.** Если в папку `data/_import/` положить карточку объекта
(название, размеры, цвет, картинки, продавец и цена), программа покажет её и
предложит принять или отклонить. Принятый объект попадает на склад с пометкой
«не подтверждено», пока человек не подтвердит его руками. Карточки готовит
отдельный помощник — сама программа по фотографиям ничего не распознаёт.

## Чего программа делать не будет

Сознательно вынесено за пределы первой версии, чтобы не растянуть её на годы:

- Подбор расстановки искусственным интеллектом и поиск картинок мебели
- Трёхмерная визуализация
- Обмен объектами между разными проектами
- Несколько пользователей, регистрация, вход по паролю
- Работа с планшета и телефона

Часть этого есть в исходной постановке и, возможно, появится позже — но отдельной
работой, а не довеском к этой.

## Как принимались решения

Проектирование велось **картой пути** — задачей на GitHub, к которой были
прицеплены вопросы, требующие решения:

**[Карта: техническое задание на планировщик мебели](https://github.com/UncleHobbot/HousePlan/issues/1)**

Каждый вопрос разбирался отдельно, ответ записывался. Карта закрыта: решений,
которые нужно было принять до написания кода, не осталось. Сами решения и
объяснения, почему именно так, лежат в `docs/adr/` — от того, как устроена
геометрия помещения, до формата файла проекта.

## Что где лежит

| Путь | Что это |
|---|---|
| `task.txt` | Исходная постановка от заказчика, как она была написана |
| `README.md` | Этот файл — общее описание для человека |
| `CLAUDE.md` | Инструкции для агентов: правила, ограничения, состояние проекта |
| `docs/` | Техническое задание: поведение программы и модель данных |
| `docs/adr/` | Принятые решения и почему так |
| `docs/agents/` | Настройки рабочих процессов: где задачи, какие метки, как ведём карту |
| `research/` | Находки исследований — что умеют существующие программы, какие есть библиотеки |
| `tasks/` | Рабочие записи по ходу дела: план текущей задачи и накопленные уроки |
| `shared/` | Типы модели данных и правила геометрии, общие для сервера и веб-части |
| `backend/` | Сервер: раздаёт приложение, читает и сохраняет файлы проектов, приём карточек |
| `frontend/` | Веб-часть: каталог проектов, редактор помещений, план этажа, склад объектов |

## Как это устроено внутри

Одна страница в браузере и небольшой сервер на Node.js, общая модель данных на
двоих. План рисуется на холсте через [Konva](https://konvajs.org/), точные размеры
пересчитывает [planegcs](https://github.com/Salusoft89/planegcs) — решатель
геометрических ограничений (та же математика, что в чертёжных программах). Своей
математики для размеров в проекте нет: за неё отвечает planegcs.

Редактор помещения разделён на три части, чтобы правки не задевали лишнего:
правила редактирования (`useEditorSession`), рисование (`roomCanvas`) и боковые
карточки (`panels`).

## Разработка

Нужен Node.js 20+. Все команды — из корня репозитория:

```bash
npm install            # один раз
npm test               # прогнать все тесты
npm run build          # собрать всё: общие типы, сервер, веб-часть
npm run start          # запустить сервер: http://localhost:3000
```

Для правок веб-части удобнее режим разработки: в одном окне `npm run
dev:backend`, во втором `npm run dev:frontend` — и открывать адрес, который
покажет vite. Данные лежат в папке `data/` (в git не попадают): резервная
копия — скопировать папку.

Готовый контейнер собирается автоматически при отправке изменений в `main` и
публикуется в GitHub Container Registry. Локально тот же образ можно проверить
командой `docker build -t houseplan .`; папку данных при запуске подключают к
`/data`.

## Где это будет работать

Домашний сервер Synology DS923+, контейнер Docker, доступ только из домашней сети.
Отдельная база данных не нужна: единицы домов и десятки объектов помещаются в файл.
