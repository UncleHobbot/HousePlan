# Где ведём задачи: GitHub

Задачи и описания требований для этого проекта живут в GitHub Issues. Все действия
выполняем через утилиту `gh` (официальная программа GitHub для командной строки).

## Как работать

- **Создать задачу**: `gh issue create --title "..." --body "..."`. Для многострочного
  текста удобнее передавать его через heredoc (способ вставить длинный текст прямо
  в команду).
- **Прочитать задачу**: `gh issue view <номер> --comments` — вместе с комментариями и
  метками.
- **Список задач**: `gh issue list --state open --json number,title,body,labels,comments --jq '[.[] | {number, title, body, labels: [.labels[].name], comments: [.comments[].body]}]'`, добавляя фильтры `--label` и `--state` по необходимости.
- **Написать комментарий**: `gh issue comment <номер> --body "..."`
- **Поставить или снять метку**: `gh issue edit <номер> --add-label "..."` и `--remove-label "..."`
- **Закрыть задачу**: `gh issue close <номер> --comment "..."`

Нужный репозиторий `gh` определяет сам по настройкам git, если запускать команды
внутри папки проекта.

## Считаем ли pull request'ы заявками

**Нет.** _(Если поменять на «да», разбор задач начнёт втягивать в общую очередь ещё и
pull request'ы от посторонних. Эту настройку читает навык разбора задач.)_

Pull request — это предложение изменений в коде от стороннего человека. В проектах с
открытым исходным кодом такое предложение часто и есть заявка на доработку. У нас
проект закрытый, посторонних участников нет, поэтому разбираем только задачи.

Если когда-нибудь понадобится включить, работает это так: у pull request'ов те же
метки и те же состояния, что у задач, только команды другие —

- **Прочитать**: `gh pr view <номер> --comments`, а `gh pr diff <номер>` покажет сами
  изменения в коде.
- **Список чужих pull request'ов**: `gh pr list --state open --json number,title,body,labels,author,authorAssociation,comments`, затем оставить только те, где `authorAssociation` равно `CONTRIBUTOR`, `FIRST_TIME_CONTRIBUTOR` или `NONE` (то есть отбросить свои и коллег — `OWNER`, `MEMBER`, `COLLABORATOR`).
- **Комментарий, метки, закрытие**: `gh pr comment`, `gh pr edit --add-label` и `--remove-label`, `gh pr close`.

Важная тонкость: у задач и pull request'ов в GitHub общая нумерация. Поэтому просто
«#42» может оказаться и тем и другим — проверяем через `gh pr view 42`, а если не
нашлось, то `gh issue view 42`.

## Если навык говорит «опубликовать в трекер задач»

Значит, создать задачу в GitHub Issues.

## Если навык говорит «взять нужную заявку»

Значит, выполнить `gh issue view <номер> --comments`.
