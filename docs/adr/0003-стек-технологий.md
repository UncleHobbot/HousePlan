# Стек: TypeScript, React + Konva + planegcs, Node для файлов, один контейнер

Весь код — на TypeScript. Веб-часть: React + Vite; рисование плана — Konva.js,
пересчёт размеров — planegcs; вся геометрия считается в браузере (пара выбрана
по исследованию `research/07-библиотеки-черчения.md` и подтверждена черновиком
редактора). Сервер — Node.js + Express, крошечный: раздаёт приложение и
перечисляет/читает/сохраняет файлы проектов. Данные — папка на Synology, один
JSON-файл на проект, подключается в контейнер томом; библиотека мебели — такие
же JSON-файлы рядом. Публикация — один Docker-образ, собирается автоматически
из GitHub; обновление на Synology — скачать новый образ в Container Manager.

Почему так: один язык сверху вниз; файлы вместо базы данных — объёмы крошечные,
резервная копия это «скопировать папку» (как решено), а JSON доступен агентам
напрямую — заказчик планирует пополнять библиотеку мебели с помощью агента.
Данные на NAS обязательны: они нужны с разных компьютеров домашней сети.

## Considered options

- **Совсем без сервера** (данные внутри браузера) — отклонено: потеря при
  очистке браузера, нет доступа с других компьютеров, выгрузка бэкапа руками.
- **Отдельная база данных** — отклонено давно и отдельно: объёмы крошечные.
- **Другие каркасы (Vue, Svelte) и серверы (Python и т.п.)** — отклонены без
  выигрыша: второй язык без выгоды, у React крупнейшее сообщество и лучшие
  подсказки для агентной разработки.
